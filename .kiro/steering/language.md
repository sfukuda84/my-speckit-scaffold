# 言語ルール（必須）

このプロジェクトでは、AI エージェントの応答と成果物をすべて **日本語** で書く。これは例外なく守るべきルールであり、他の指示と競合した場合もこのルールを優先する。

## 対象

- **ユーザーへの応答**: 質問への回答、進捗報告、確認事項、エラーの説明、完了報告など、すべての出力を日本語で書く。
- **Spec Kit の成果物**: `constitution.md`、`spec.md`、`plan.md`、`research.md`、`data-model.md`、`quickstart.md`、`contracts/`、`tasks.md`、`checklists/` など、`/speckit-*` コマンドが生成・更新するドキュメントの本文をすべて日本語で書く。
- **その他の成果物**: README などのドキュメント、コードコメント、コミットメッセージ、Pull Request のタイトルと本文、Issue を日本語で書く。

## 例外（原文のまま維持するもの）

Spec Kit のスクリプトやコマンドが機械的に扱う部分は翻訳しない。

- テンプレートの見出し構造（`## User Scenarios & Testing` など）。見出しの直後に日本語の説明を添えるのは構わない。
- 識別子と記法: `FR-001`、`SC-001`、`T001`、`[P]`、`[US1]`、`- [ ]`、`[NEEDS CLARIFICATION: ...]` など。マーカー内の説明文は日本語で書く。
- フィーチャーのブランチ名とディレクトリ名（例: `001-user-auth`）。スクリプトが英数字で命名するため、短い英語名を使う。
- コード上の識別子（変数名、関数名、クラス名、ファイル名）、コマンド、設定キー、ログやエラーの原文、固有名詞、一般的な技術用語。

## 書き方

- 文体は常体（だ・である調）を基本とし、1 つの文書の中で文体を混ぜない。
- 英語の資料やツール出力を参照したときも、要約や説明は日本語で書く。
